# Библиотека промптов

Эта папка — централизованное хранилище промптов для проекта **Prompt Engineering Lab**.
Здесь собираются проверенные и экспериментальные формулировки, которые используются
в задачах автоматизации с помощью LLM.

## Назначение библиотеки

Библиотека решает несколько задач:

- **Переиспользование.** Один и тот же промпт не изобретается заново в каждом
  эксперименте — его можно взять из библиотеки и адаптировать.
- **Версионирование.** Промпты хранятся в Git, поэтому видно, как формулировка
  менялась со временем и какая версия давала лучший результат.
- **Сравнение.** Промпты одной категории лежат рядом, что упрощает их
  сопоставление в экспериментах (см. `experiments/`).
- **Документирование.** У каждого промпта есть описание: задача, ожидаемый формат
  ответа, ограничения и известные слабые места.

## Структура и категории

Промпты группируются по типу задачи. Ниже — основные категории.

### Классификация текста

Отнесение текста к одной или нескольким заранее заданным категориям:
тональность, тема, спам/не спам, приоритет обращения и т.п.
Ключевые аспекты: чёткий список классов, правила для пограничных случаев,
формат вывода (метка + уверенность).

### Извлечение данных

Выделение из неструктурированного текста конкретных сущностей: имён, дат,
сумм, адресов, артикулов. Ключевые аспекты: точное описание полей, обработка
отсутствующих значений, запрет на домысливание.

### Генерация контента

Создание текста по заданным параметрам: описание товара, ответ клиенту,
черновик письма. Ключевые аспекты: тон, объём, целевая аудитория, запрещённые
формулировки, структура.

### Анализ отзывов

Разбор пользовательских отзывов: выделение тем, сильных и слабых сторон,
тональности, конкретных жалоб и предложений. Ключевые аспекты: разделение
фактов и эмоций, цитирование фрагментов, сводка без потери смысла.

### Структурированный JSON

Получение от модели строго валидного JSON по заданной схеме. Ключевые аспекты:
описание схемы, типы полей, обязательные и опциональные ключи, поведение при
неполных данных, запрет на лишний текст вокруг JSON.

## Соглашения об именовании

Рекомендуется именовать файлы по шаблону:

`<категория>_<задача>_v<номер>.md`

Пример: `classification_sentiment_v2.md`, `extraction_invoice_fields_v1.md`.

Внутри файла полезно указывать: цель промпта, сам текст промпта, ожидаемый
формат ответа, известные ограничения и ссылку на эксперимент, в котором промпт
проверялся.
